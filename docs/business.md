# 信贷业务链路与面试说明

## 被测业务

贷款申请已提交、等待审批时，申请人撤回申请。前置条件是本次贷款处于 `SUBMITTED_AND_PENDING_APPROVAL`，期望终态是 `WITHDRAWN_BY_CLIENT`。撤回响应只证明请求被受理，最终结果必须查询确认。

参考 [Apache Fineract](https://github.com/apache/fineract)，阅读基线 commit `1089f9bdd02030770b32660dcaef4a13df41c28e`。上游 `LoanWithdrawnByApplicantIntegrationTest` 展示创建客户、产品、贷款申请和撤回断言；`LoanRequestBuilders` 展示贷款申请数据构造。LoanLab 当前使用独立模拟实现，并未运行这些上游集成测试。

## 为什么轮询

系统可能异步处理状态变更。持续查询同一贷款，到第一次成功或总预算耗尽停止。预算耗尽后仍待审批，能确认“在约定时间内未观察到期望终态”，不能仅凭这个现象推断服务端从未执行、队列一定丢失或数据库一定失败。

本演示预算 5 个虚拟秒、查询间隔 1 个虚拟秒。生产适配需由接口 SLA 决定，并考虑查询延迟、网络超时和最终一致性。

## 为什么不盲目重试写操作

网络超时只代表客户端没有拿到响应，不代表服务端没有处理。先查询状态；确需重试时必须了解接口的幂等契约。本项目阻止 Agent 自动重复撤回，并未实现真实服务端幂等键。

## 面试时可以演示的三个问题

1. “接口 200 为什么还失败？”切换 noop 场景，展示响应、最终状态和 FAIL 的证据链。
2. “Agent 怎么避免乱操作？”展示错误 loan_id、未知工具、顺序校验的自动化测试；代码在产生副作用之前拒绝。
3. “LLM 说成功就算成功吗？”展示模型提前输出 PASS 的测试：没有执行代码断言，结果仍是 ERROR。

## 简历描述（仅覆盖已实现部分）

**LoanLab：面向信贷申请撤回的受控测试 Agent（个人项目）**

- 围绕待审批贷款撤回链路，构建自然语言任务、白名单工具调用、状态轮询、代码断言与证据报告的完整演示，提供确定性模板和 DeepSeek 接入模式。
- 对工具参数、调用顺序和贷款资源 ID 实施执行前校验，限制模型调用预算并禁止重复撤回；区分业务失败、依赖异常与非法调用，避免以 HTTP 成功或模型文本替代业务验证。
- 构建正常、延迟生效、假成功和查询异常等受控场景，配套自动化回归、固定评测集及本地工作台，支持轨迹查看与 JSON 报告归档。

真实 API 调通后可补充实测记录；完成真实 Fineract 适配后再写相关成果。不要写生产上线、金融客户采用、真实缺陷发现数或未测过的准确率。

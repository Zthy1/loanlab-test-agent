# 信贷业务链路与面试说明

## 被测业务

贷款申请已提交、等待审批时，申请人撤回申请。前置条件是本次贷款处于 `SUBMITTED_AND_PENDING_APPROVAL`，期望终态是 `WITHDRAWN_BY_CLIENT`。撤回响应只证明请求被受理，最终结果必须查询确认。

参考 [Apache Fineract](https://github.com/apache/fineract)，阅读基线 commit `1089f9bdd02030770b32660dcaef4a13df41c28e`。上游 `LoanWithdrawnByApplicantIntegrationTest` 展示创建客户、产品、贷款申请和撤回断言；`LoanRequestBuilders` 展示贷款申请数据构造。LoanLab 提供独立模拟与真实 HTTP 适配；已执行本项目的四条真实业务用例，未运行上游 Java 集成测试。

## 为什么轮询

系统可能异步处理状态变更。持续查询同一贷款，到第一次成功或总预算耗尽停止。预算耗尽后仍待审批，能确认“在约定时间内未观察到期望终态”，不能仅凭这个现象推断服务端从未执行、队列一定丢失或数据库一定失败。

本演示预算 5 个虚拟秒、查询间隔 1 个虚拟秒。生产适配需由接口 SLA 决定，并考虑查询延迟、网络超时和最终一致性。

## 为什么不盲目重试写操作

网络超时只代表客户端没有拿到响应，不代表服务端没有处理。先查询状态；确需重试时必须了解接口的幂等契约。本项目阻止 Agent 自动重复撤回，并未实现真实服务端幂等键。

## 面试时可以演示的三个问题

1. “接口 200 为什么还失败？”切换 noop 场景，展示响应、最终状态和 FAIL 的证据链。
2. “Agent 怎么避免乱操作？”展示错误 loan_id、未知工具、顺序校验的自动化测试；代码在产生副作用之前拒绝。
3. “LLM 说成功就算成功吗？”展示模型提前输出 PASS 的测试：没有执行代码断言，结果仍是 ERROR。

## 简历描述（仅覆盖已验证部分）

**LoanLab：基于 DeepSeek 的信贷业务测试 Agent（个人项目）**

- 基于 Apache Fineract 搭建 Docker / PostgreSQL 隔离测试环境，完成客户、贷款产品、申请数据准备，验证待审批撤回、审批后拒绝撤回、终态重复请求和贷款状态隔离四类业务规则。
- 实现受控工具调用，对参数、顺序和贷款 ID 执行前校验；代码负责状态轮询与断言，区分业务不符、依赖异常和非法调用，避免模型文本或 HTTP 成功覆盖业务失败。
- 设计模板与 DeepSeek 的固定任务配对评测，从分类匹配、表达适配、越界执行、Token 和耗时评估收益与代价，并完成真实模型连接 Fineract 的完整链路实测。
- 配套 42 项自动化检查、故障变体和 CI，归档请求轨迹、最终状态与数据清理残留，提供工作台及可下载运行证据。

不要将单次 8 条任务的匹配结果写成生产准确率，不写真实银行上线或客户采用；当前未完成服务端多角色越权验证和并发竞争测试。
